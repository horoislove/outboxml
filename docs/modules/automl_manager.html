AutoMLResult

Container class for AutoML execution results.

Stores all results, metrics, and metadata from an AutoML training run, including feature selection results, hyperparameters, model metrics, deployment decisions, and execution times.

Parameters:

group_name (str) – Name of the model group for this AutoML run.

Variables:

  • start_run_time – Timestamp when the AutoML run started.

  • run_time – Dictionary mapping stage names to execution timestamps.

  • features_for_research – List of features selected for research.

  • new_features – Dictionary mapping model names to lists of new features.

  • new_hp – Dictionary mapping model names to optimized hyperparameters.

  • ds_manager_result – Dictionary mapping model names to DSManagerResult objects.

  • metrics – Dictionary with ‘train’ and ‘test’ keys containing metrics.

  • figures – List of Plotly figures for visualization.

  • model_result_for_service – List of model results formatted for service deployment.

  • result_pickle_name – Name of the pickle file containing results.

  • compare_metrics_df – DataFrame comparing metrics between current and previous models.

  • compare_business_metric – DataFrame with business metric comparisons.

  • end_time_run – Timestamp when the AutoML run finished.

  • deployment – Boolean indicating whether models were deployed to production.

  • all_models_config – Path or name of the all models configuration file.

  • business_metric – Dictionary of business metrics.

Examples

result = AutoMLResult(group_name="Titanic_Model_v1")
print(result.group_name)
# Output: Titanic_Model_v1

Wrapper for MLFlow to perform artifact logging and experiment tracking.

Provides a convenient interface for logging AutoML results to MLFlow, including models, metrics, artifacts, and hyperparameters. Supports nested runs for organizing multiple models within a single experiment.

Parameters:

  • group_name (str) – Name of the model group/run. Defaults to ‘example’.

  • project (str) – Project name (currently not used). Defaults to ‘test_project’.

  • results_path (str) – Path to the results directory containing artifacts. Defaults to ‘results’.

  • mlflow_tracking_uri (str) – MLFlow tracking server URI. Defaults to ‘http://localhost:5000’.

log_results(automl_results, *tags)[source]

Log AutoML results to MLFlow.

Logs all artifacts, metrics, and parameters from an AutoML run to MLFlow. Creates a main run for the group and nested runs for each model. Logs: - Log files - Model pickle files - Model configurations - Feature lists (numerical and categorical) - Training and test metrics - Hyperparameters - Business metrics - Deployment decision tag

Parameters:

  • automl_results (AutoMLResult) – AutoMLResult object containing all results to log.

  • *tags –

    Variable number of additional tag arguments (currently not used).

Returns:

None

Return type:

None

Note

  • Creates nested runs for each model in the results

  • Errors during artifact logging are caught and logged but don’t stop the process

  • Business metrics are logged if available

Examples

result = AutoMLResult(group_name="Titanic_Model_v1")
# ... populate result with data ...
wrapper = MLFlowWrapper(experiment_name="Titanic", group_name="Titanic_Model_v1")
wrapper.log_results(result)
# Results logged to MLFlow with nested runs for each model

Main class for conducting AutoML pipeline.

Orchestrates the complete AutoML workflow including feature selection, hyperparameter tuning, model training, comparison with previous models, deployment decisions, and result logging. Extends DataSetsManager to leverage dataset management functionality.

Parameters:

  • auto_ml_config (str or AutoMLConfig) – Path to AutoML configuration file or AutoMLConfig object.

  • models_config (str or AllModelsConfig) – Path to models configuration file or AllModelsConfig object defining all models to be trained.

  • extractor (Extractor, optional) – Optional interface for fetching and transforming input data. Defaults to None.

  • business_metric (BaseMetric, optional) – Optional interface for computing business-specific metrics. Should return a dictionary like {‘metric_name’: metric_value}. Defaults to None.

  • compare_business_metric (BaseCompareBusinessMetric, optional) – Optional interface for comparing business metrics and applying thresholds. Defaults to None (uses BaseCompareBusinessMetric).

  • external_config (object, optional) – Optional external configuration object. Defaults to None.

  • retro (bool) – Whether to perform retrospective feature selection. Defaults to True.

  • hp_tune (bool) – Whether to perform hyperparameter tuning. Defaults to True.

  • async_mode (bool) – Whether to run model training asynchronously. Defaults to False.

  • use_temp_files (bool) – Whether to use temporary files for data processing. Defaults to False.

  • model_timeout_seconds (int, optional) – Maximum time in seconds for training a single model. Defaults to None (no timeout).

  • grafana_connection (object, optional) – Database connection object for Grafana export. Passed to pd.to_sql(). Defaults to None.

  • models_dict (dict, optional) – Optional dictionary of pre-initialized models. Defaults to None.

Variables:

  • models_dict – Dictionary of pre-initialized models.

  • timeout – Maximum time for model training.

  • _business_metric – Business metric calculator.

  • _compare_business_metric – Business metric comparator.

  • _hp_tune – Whether hyperparameter tuning is enabled.

update_models(send_mail=False, parameters_for_optuna=None)[source]

Execute the complete AutoML pipeline to update models.

Orchestrates the full AutoML workflow: 1. Feature selection (if retro=True) 2. Hyperparameter tuning (if hp_tune=True) 3. Model training 4. Result saving 5. Comparison with previous models 6. Deployment decision 7. Review (email or HTML report) 8. MLFlow logging

Parameters:

  • send_mail (bool) – Whether to send email notifications. If False, generates HTML report instead. Defaults to False.

  • parameters_for_optuna (dict, optional) – Optional dictionary mapping model names to custom Optuna parameter functions for hyperparameter tuning. Defaults to None.

Returns:

AutoMLResult object containing all results, metrics, and metadata.

Return type:

AutoMLResult

Note

  • Errors are caught and logged, but results are still saved to MLFlow

  • Status dictionary is updated throughout the process

  • Execution times are recorded for each stage

Examples

automl = AutoMLManager(...)
result = automl.update_models(send_mail=True)
print(f"Deployment: {result.deployment}")
print(f"New features: {result.new_features}")

hp_tuning(parameters_for_optuna=None)[source]

Perform hyperparameter tuning for all models.

Uses Optuna to find optimal hyperparameters for each model through cross-validation. Supports custom parameter search spaces via parameters_for_optuna.

Parameters:

parameters_for_optuna (dict, optional) – Optional dictionary mapping model names to custom Optuna parameter functions. Each function should define the search space for that model. Defaults to None.

Returns:

Dictionary mapping model names to optimized hyperparameters. Empty dictionary for models that failed tuning.

Return type:

dict

Note

  • Errors during tuning are logged but don’t stop the process

  • Uses the configured sampler, scoring function, and CV folds

  • Respects model_timeout_seconds if set

  • Returns empty dict for models that fail tuning

Examples

def custom_params(trial):
    return {'learning_rate': trial.suggest_float('learning_rate', 0.01, 0.3)}
parameters = {'model1': custom_params}
new_hp = automl.hp_tuning(parameters_for_optuna=parameters)
print(new_hp['model1'])
# {'learning_rate': 0.15, ...}

deployment()[source]

Make deployment decision based on quality criteria.

Evaluates whether models meet the configured quality thresholds for deployment. Checks both business metrics and comparison business metrics against configured thresholds. Sets deployment flag to True only if all criteria are met.

Returns:

None

Return type:

None

Note

  • Deployment is set to True only if ALL criteria are met

  • Uses metric_growth_value from inference_criteria config

  • For CompareBusinessMetric, checks if difference exceeds threshold

  • For other metrics, checks if metric value is better than threshold

Examples

# True if all criteria met, False otherwise

Generate review report (email or HTML) for AutoML execution.

Creates and sends either an email notification or generates an HTML report based on the send_mail flag. Includes success reports or error reports depending on execution status.

Parameters:

  • email (EMail) – Email instance for sending notifications.

  • send_mail (bool) – Whether to send email. If False, generates HTML report instead.

  • error (Exception, optional) – Optional exception that occurred during execution. If provided, generates error report. Defaults to None.

Returns:

None

Return type:

None

Note

  • If send_mail=True and no error: sends success email

  • If send_mail=True and error: sends error email

  • If send_mail=False and no error: generates HTML success report

  • If send_mail=False and error: generates HTML error report

  • Optionally sends release notification if models were released to Git

Examples

automl.review(email, send_mail=True)
# Sends email notification
